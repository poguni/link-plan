# 링크 플랜 — Claude Code 단계별(Phase) 프롬프트

이 폴더(`linkplan-design-handoff/`)를 프로젝트 루트에 두고 Claude Code 를 실행한 뒤, **Phase 순서대로 프롬프트를 하나씩 붙여 넣으세요.**
각 Phase 는 (1) 목표 (2) 붙여 넣을 프롬프트 (3) 완료 기준 (4) 사용자가 직접 할 일 로 되어 있습니다.

## 진행 방법

- 한 Phase 가 끝나고 **완료 기준을 확인한 뒤** 다음 Phase 로 넘어갑니다. 한 번에 여러 Phase 를 시키지 마세요.
- 각 Phase 는 새 대화(`/clear`)로 시작해도 됩니다. `CLAUDE.md` 가 규칙을 다시 알려 주기 때문입니다.
- Phase 마다 끝나면 git 커밋을 남깁니다(프롬프트에 포함되어 있습니다).
- 문서 우선순위: **시안(`mockups/`) → `DESIGN.md` → `tokens.css`**, 기능·데이터는 `PRD.md`.
- Supabase 대시보드에서 하는 작업은 Claude Code 가 대신할 수 없습니다. 각 Phase 의 「직접 할 일」을 먼저 하세요.

|---|---|---|---|---|

## 공통 머리말 (모든 Phase 프롬프트 맨 위에 붙이세요)

```text
[공통 규칙]
- 먼저 CLAUDE.md, DESIGN.md 를 읽고 시작해. 기능·데이터는 PRD.md 를 근거로 해.
- 기술 스택은 Vanilla JS(ES 모듈), 빌드 도구 없음, SortableJS, supabase-js(CDN)야. 프레임워크·번들러를 추가하지 마.
- 컴포넌트 CSS 에 색 코드를 직접 쓰지 말고 tokens.css 변수만 써. 이모지는 쓰지 말고 icons.svg(Lucide)만 써.
- 시안(mockups/*.html)과 문서가 다르면 시안 → DESIGN.md → tokens.css 순서로 따라.
- service_role 키는 프런트엔드 코드나 저장소에 절대 넣지 마.
- 화면 문구와 주석은 한국어 존댓말로, 맞춤법과 띄어쓰기를 확인해서 써.
- 작업 전에 계획을 짧게 말해 주고, 끝나면 무엇을 바꿨는지와 내가 직접 확인할 방법을 알려 줘.
- 이번 Phase 범위를 벗어나는 기능은 만들지 마. 필요하면 다음 Phase 로 미루고 그 사실을 알려 줘.
```

## Phase 0. 프로젝트 준비

**목표** 폴더 구조와 개발 환경을 만듭니다. 기능은 아직 만들지 않습니다.

```text
[공통 규칙]을 지켜서 Phase 0 을 진행해 줘.

할 일
1. 저장소 구조를 만들어 줘(DESIGN.md 11절 기준).
   index.html, css/(tokens.css, base.css, components.css, view-board.css, view-link.css),
   js/(app.js, state.js, api.js, theme.js, board.js, link.js, admin.js), assets/icons.svg
   docs/ 폴더에는 PRD.md, DESIGN.md, mockups/, previews/, sample-data.json 을 옮겨 둬.
   tokens.css 와 icons.svg 는 제공된 파일을 그대로 css/, assets/ 로 복사해.
2. 빌드 없이 실행할 수 있게, 로컬 정적 서버 실행 방법을 README.md 에 적어 줘(예: npx serve 또는 python -m http.server).
3. index.html 은 lang="ko", viewport 메타, tokens.css 링크, icons.svg 인라인 삽입 자리만 있는 빈 셸로 만들어 줘.
4. .gitignore 를 만들고(.env, .DS_Store 등), config.js 에 SUPABASE_URL / SUPABASE_ANON_KEY 자리만 만들어 줘(값은 비워 두기).
5. git 저장소를 초기화하고 「chore: 프로젝트 구조 생성」으로 커밋해 줘.

하지 말 것: 화면·기능 구현, 외부 라이브러리 설치(SortableJS 와 supabase-js 는 이후 Phase 에서 CDN 으로 추가).
```

**완료 기준** 서버를 켜면 빈 페이지가 열리고 콘솔 오류가 없음 / `docs/` 에 문서가 있음 / 커밋 1개.

**직접 할 일** (지금 해 두면 좋음) Supabase 새 프로젝트 만들기, 관리자로 쓸 이메일 정하기.

## Phase 1. 디자인 시스템과 셸 (정적)

**목표** `data-theme` × `data-view` 6가지가 전환되는 앱 뼈대와 공통 컴포넌트를 만듭니다. 데이터는 하드코딩(빈 상태)입니다.

```text
[공통 규칙]을 지켜서 Phase 1 을 진행해 줘. 근거: DESIGN.md 0~4절, PRD.md 6-1~6-5.

할 일
1. base.css: 리셋, 서체(테마별 Google Fonts 지연 로드), .ic 아이콘 클래스, 포커스 링, prefers-reduced-motion 처리.
2. theme.js: <html> 의 data-theme(clean|night|pastel) 과 data-view(board|link) 를 바꾸는 함수. 선택값은 localStorage 에 저장하고, 새로고침 후에도 유지해. (계정 저장은 Phase 6 에서 붙일 거라 지금은 하지 마.)
3. 셸 3종(DESIGN.md 1절): clean=사이드바 232px(링크 뷰에서는 72px 레일), night·pastel=상단바 64px + 좌측 목표 패널 248px(링크 뷰에서는 패널 숨김).
   뷰 전환 UI(사이드바 항목 / 상단바 세그먼트), 기간 세그먼트(일일·주간·월간·연간)와 이전/다음, 「새 할 일」 버튼까지 배치해. 동작은 아직 연결하지 않아도 돼.
4. components.css: 할 일 카드, 단계 칩, 진행 링, 진행 막대, 세그먼트, 버튼, 점선 추가 슬롯, 빈 상태, 토스트를 DESIGN.md 4절대로 만들어.
5. 임시 테스트 페이지(dev.html)에 컴포넌트와 테마·뷰 전환 버튼을 모아 두고, 6가지 조합에서 확인할 수 있게 해 줘.
6. Playwright 등으로 1280×820 스크린샷 6장을 찍어 docs/previews/ 의 시안 스크린샷과 나란히 비교해서, 다른 곳을 목록으로 알려 줘. (빌드 도구는 아니지만 검수용으로만 devDependency 를 써도 돼. 배포물에는 포함하지 마.)

완료하면 git 커밋: 「feat: 디자인 시스템과 테마·뷰 셸」
```

**완료 기준** 6가지 조합이 새로고침 없이 전환됨 / 색 코드 하드코딩 0건(`grep -E "#[0-9A-Fa-f]{6}" css/components.css`) / 6장 스크린샷이 시안과 눈으로 같음(셸 부분).

## Phase 2. 보드 뷰 (정적 데이터)

**목표** 3열 칸반과 좌측 목표 패널, 드래그 앤 드롭을 `sample-data.json` 으로 완성합니다.

```text
[공통 규칙]을 지켜서 Phase 2 를 진행해 줘. 근거: DESIGN.md 5·7절, PRD.md P0-3·P0-4.

할 일
1. state.js: docs/sample-data.json 을 읽어 메모리 상태로 보관하고, 구독(변경 알림) 방식의 아주 작은 저장소를 만들어 줘. 상태 변경은 함수(예: setTaskStatus)로만 하게 해.
2. board.js: 시작 전 / 진행 중 / 완료 3열, 열 머리(아이콘·이름·개수), 카드 렌더링, 열 끝의 「새 할 일 추가」 점선 슬롯.
   좌측 목표 패널(연간→월간→주간 요약 카드, 진행 막대)과 목표 클릭 시 해당 목표에 연결된 할 일만 보이는 필터(다시 클릭하면 해제), 「연결 없음」 필터.
3. SortableJS(CDN)로 열 사이 이동 = 상태 변경. 드래그 중 카드 기울임과 자리표시자, 놓인 열 강조는 DESIGN.md 7절 규칙을 따라.
   낙관적 업데이트 구조로 만들어 줘: 상태 변경 함수가 실패하면 원래 열로 되돌리는 코드 경로를 지금 만들어 두고(지금은 실패하지 않음), 토스트로 알려 줘.
4. 진행률 계산 함수(progress.js): PRD 「진행률 계산 규칙」 대로 완료만 반영하고, 카드가 완료로 바뀌면 연결된 주간·월간·연간 진행률이 즉시 갱신되게 해. 단위 테스트 없이도 되지만 콘솔에서 검증할 수 있는 예시 3개를 README 에 적어 줘.
5. 키보드 대안: 카드에서 Enter → 「상태 변경」 메뉴(시작 전/진행 중/완료).
6. pastel 전용 장식(마스킹테이프, 배너, 점무늬)은 시안대로 넣되 기능은 다른 테마와 같아야 해.
7. 세 테마 보드 뷰를 스크린샷으로 찍어 시안과 비교하고 다른 점을 고쳐 줘.

완료하면 git 커밋: 「feat: 보드 뷰와 드래그 앤 드롭(정적 데이터)」
```

**완료 기준** 카드를 열 사이로 끌어 상태가 바뀜(마우스·터치·키보드) / 완료 시 진행률 갱신 / 세 테마 보드 스크린샷이 시안과 일치.

## Phase 3. 링크 뷰 (정적 데이터)

**목표** 노드 그래프, 연결선, 상태 트레이를 `sample-data.json` 으로 시안과 같게 만듭니다. 가장 까다로운 화면이므로 별도 Phase 로 둡니다.

```text
[공통 규칙]을 지켜서 Phase 3 을 진행해 줘. 근거: DESIGN.md 6절 전체, PRD.md 6-2.

할 일
1. link.js 의 레이아웃 함수(layout.js 로 분리해도 좋아): plans / tasks / links 를 받아 노드 좌표를 계산해. 순수 함수로 만들어서 DOM 없이 테스트할 수 있게 해.
   - 열 x 좌표·노드 폭은 tokens.css 의 --node-w, --node-pitch, --node-x0 을 따라(clean 96/400/704/1008 폭 224, night·pastel 40/360/680/1000 폭 240).
   - 부모는 자식들의 세로 중앙에 맞추고, 그룹 사이 간격은 DESIGN.md 6-2 규칙을 따라.
   - sample-data.json 으로 계산한 top 값이 DESIGN.md 6-2 표(할 일 110·174·238·302·382·446·526 등)와 일치하는지 확인하는 검증 스크립트(check-layout.js)를 만들고 결과를 알려 줘. pastel 은 +12px.
2. 노드 렌더링: 연간·월간·주간 노드(단계 라벨, 제목, n/m 완료, 진행 링), 할 일 노드(상태 아이콘, 보조 줄, 연결 배지, 끌기 손잡이), 열 머리(개수 포함), 「연결 없음 · 독립 할 일」 영역.
3. 연결선 SVG 레이어(노드 아래, pointer-events none): DESIGN.md 6-3 그대로 —
   부모 오른쪽 가운데 → 자식 왼쪽 가운데, y 가 같으면 직선, 다르면 3차 베지어(g=(x2-x1)/2), 색은 부모 단계 색, 테마별 굵기·불투명도,
   월간→할 일 직접 연결(실선 큰 곡선)과 연간→할 일 직접 연결(점선 직각 경로, 모서리 반지름 16px).
   리사이즈 후에도 노드 점과 선이 맞게 다시 그려.
4. 상태 트레이(6-5): 3칸, 개수, 드롭존, 완료 칸의 「주간 33% → 67%」 진행률 미리보기 칩. 카드를 트레이 칸으로 끌어 놓으면 상태 변경.
5. 상호작용(6-6): 노드 호버/포커스 시 연결된 선만 강조, 그래프 영역만 스크롤(트레이 고정), 연결선 클릭 시 삭제 버튼(지금은 상태에서 링크 제거만).
   점을 끌어 새 연결을 만드는 동작은 연결 규칙(단계 건너뜀 금지)을 검사하는 함수까지만 만들어 줘. 서버 검증은 Phase 6 에서 붙여.
6. 화면 폭 1024px 미만이면 링크 뷰 버튼을 비활성화하고 보드 뷰로 돌려 보내(PRD P0-12). 좁은 화면용 목록형은 Phase 8 에서 만들어.
7. 세 테마 링크 뷰 스크린샷을 시안과 비교해 다른 점을 고쳐 줘(노드 위치, 선 색, 트레이).

완료하면 git 커밋: 「feat: 링크 뷰(노드·연결선·트레이, 정적 데이터)」
```

**완료 기준** `check-layout.js` 가 DESIGN.md 좌표와 일치 / 세 테마 링크 뷰가 시안과 눈으로 같음 / 창 크기를 바꿔도 선이 어긋나지 않음.

## Phase 4. Supabase DB 와 RLS

**목표** 새 Supabase 프로젝트에 테이블·정책·뷰를 만들고 RLS 를 검증합니다. **이 Phase 는 SQL 파일을 만들고, 실행은 사용자가 대시보드에서 합니다.**

**직접 할 일 (먼저)**
1. Supabase 새 프로젝트 생성(리전: 서울 등 가까운 곳). Postgres 15 이상인지 확인.
2. Authentication → Providers → Email: **Confirm email 끄기**, 비밀번호 최소 길이 8, 「Digits and letters」 요구 사항 켜기(PRD 5-6).
3. SQL Editor 에서 아래 Phase 4 프롬프트가 만든 파일을 순서대로 실행.

```text
[공통 규칙]을 지켜서 Phase 4 를 진행해 줘. 근거: PRD.md 5-2~5-5. 이번 Phase 는 supabase/ 폴더의 SQL 파일만 만들어.
```
